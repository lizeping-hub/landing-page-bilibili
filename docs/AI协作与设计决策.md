# AI 协作与设计决策

这个项目要展示 AI 产品经理如何将产品意图、设计判断和技术探索连接起来。页面本身面向访客；协作过程留在项目材料中，供面试讲述与源码审阅。

## 用户作出的判断

用户提出 B 站品牌体验、中文单页、炫酷交互、GitHub 开源与 Pages 部署，明确了 AI 产品经理面试用途。通过多轮澄清，确定五段体验、小电视与内容卡片、最多三个兴趣、二十字弹幕、可带走的个人档案，以及统一生成的概念素材。

用户随后重构视觉和交互：统一暗黑基底，使用标志性粉色与赛博蓝，取消横向滚动，用 sticky 加纵向 3D 发牌，并要求移动端彻底卸载复杂动画。用户确认新方案后才进入开发。

## AI 完成的执行工作

- 将确认方案转成 React 状态模型、五段界面、设计变量和降级条件。
- 生成七张统一风格插画，压缩网页素材，自制三场景无声短片。
- 实现兴趣、弹幕、创作者反馈和 Canvas PNG，接入会话恢复。
- 用浏览器逐步验证操作，修正图片比例、装饰溢出、状态清理和缺少实际操作的视觉控件。
- 记录真实构建体积和验收结果，准备 GitHub Pages 自动部署配置。

## 三个可讲清楚的取舍

**视觉表现与输入稳定性。** 滚动只读取原生页面进度，不拦截滚轮或触控。CSS sticky 固定舞台，GSAP 只处理卡片景深。兴趣标签始终可点击；非当前卡片暂时退出键盘焦点，移动端全部恢复。

**沉浸内容与下载量。** 空间感主要交给插画和离线编码的视频，避免在浏览器运行完整三维场景。视频按需加载、无声、可暂停，离屏停止。全部资源约 2.28MB，构建预算检查进入自动部署流程。

**互动闭环与可带走的结果。** 兴趣决定档案标签，弹幕成为档案宣言。访客可修改昵称、生成高清 PNG，即便跳过前序互动也可生成默认档案。最后一段为整页探索提供具体结果。

## 面试展示顺序

用一句话解释目标与体验边界；演示选择兴趣、发送弹幕、切换创作者、导出档案；说明取消横向滚动和手机降级的原因；展示资源预算与实际验收；最后打开设计方案和源码，区分用户决策、AI 执行以及仍需验证的部分。

这里没有宣称模型效果、增长转化或线上用户数据。正式发布后的访问性能和用户反馈将成为下一轮迭代依据。
